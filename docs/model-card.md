# Model Card — California Housing Random Forest

## Intended use

Educational and portfolio demonstration of a reproducible regression pipeline, held-out evaluation, API serving and user-facing model limitations.

## Not intended for

- individual property valuation;
- mortgage, lending, investment or insurance decisions;
- current market-price estimation;
- decisions about people, eligibility or access to services;
- production use without independent validation and governance.

## Data

The model uses scikit-learn's California Housing dataset, derived from 1990 US Census block-group aggregates. It does not contain individual property records or personal identifiers.

Target: median block-group house value in units of $100,000.

Features: median income, house age, average rooms, average bedrooms, population, average occupancy, latitude and longitude.

## Preparation

- exact duplicate rows are removed;
- known extreme `AveRooms` and `AveOccup` artifacts are filtered transparently;
- data is split into training and held-out test sets using a fixed random state;
- the test set is not used to fit preprocessing or models.

## Models

- Linear Regression with training-fitted standardisation, retained as an interpretable baseline.
- Random Forest Regressor with fixed hyperparameters and random state, used for the API and Streamlit estimate.

## Evaluation

The pipeline reports RMSE, MAE and R² on a held-out test set. Exact values are generated by `python -m src.mlapp.pipeline` and written to `exports/metrics.json`; documentation should not hard-code unverified numbers.

## Limitations and risks

- Data reflects 1990 conditions and cannot represent current prices.
- Block-group aggregates are not individual properties.
- Geographic and socioeconomic patterns in historical data can encode structural inequities.
- Metrics on one split do not guarantee generalisation to other regions or periods.
- Random Forest feature importance is not causal explanation.
- Estimates can be wrong even for inputs within accepted ranges.

## Safety controls

- constrained request schema and finite-number validation;
- canonical feature order;
- versioned model metadata;
- safe errors for missing, corrupt or invalid artifacts;
- explicit disclaimers in the API, Streamlit app and documentation;
- no user-controlled model uploads or artifact paths.

## Maintenance

When data, preprocessing, dependencies, features or hyperparameters change, retrain the model, rerun tests and CI, compare metrics, update this model card and record the change in `CHANGELOG.md`.
