# Model Card — California Housing Selected Regressor

## Intended use

Educational and portfolio demonstration of a reproducible regression pipeline, validation-based model selection, final held-out evaluation, API serving and user-facing model limitations.

## Not intended for

- individual property valuation;
- mortgage, lending, investment or insurance decisions;
- current market-price estimation;
- decisions about people, eligibility or access to services;
- production use without independent validation and governance.

## Data

The project uses scikit-learn's California Housing dataset, derived from 1990 US Census block-group aggregates. It does not contain individual property records or personal identifiers.

Target: median block-group house value in units of $100,000.

Features: median income, house age, average rooms, average bedrooms, population, average occupancy, latitude and longitude.

## Preparation and row accounting

The fixed demonstration cleaning sequence is auditable:

- raw rows: **20,640**;
- exact duplicates removed: **0**;
- rows with `AveRooms >= 30` removed: **24**;
- rows with `AveOccup >= 15` removed after prior filtering: **19**;
- final rows: **20,597**.

These are transparent fixed filters for extreme aggregate values. They are not claimed to be statistically optimal outlier treatment.

## Evaluation design

JR05 uses deterministic train/validation/final-test separation:

1. create the final test split first using 20% of cleaned rows and `random_state=42`;
2. split the remaining development data into train and validation using 25% of the development rows for validation and `random_state=43`;
3. fit the two fixed candidate models on training rows;
4. compare candidates only on validation RMSE;
5. select the lower-validation-RMSE candidate, with an exact tie assigned to the simpler Linear Regression baseline;
6. refit the selected model on train + validation;
7. evaluate that selected final model once on the untouched final test set.

Row counts:

- train: **12,357**;
- validation: **4,120**;
- final test: **4,120**;
- selected-model refit rows: **16,477**.

The final test set does not drive model selection.

## Models

### Linear Regression baseline

- `fit_intercept=True`;
- training-fitted `StandardScaler`;
- retained as the simple baseline.

### Random Forest candidate

- `n_estimators=200`;
- `max_depth=14`;
- `random_state=42`;
- `n_jobs=-1`.

## Validation model-selection evidence

| Model | RMSE | MAE | R² |
|---|---:|---:|---:|
| Linear Regression baseline | 0.6877 | 0.5023 | 0.6454 |
| Random Forest | **0.5356** | **0.3529** | **0.7850** |

Selected model: **Random Forest**, because it had the lower validation RMSE.

## Final held-out test evidence

After refitting Random Forest on train + validation:

- RMSE: **0.4771**
- MAE: **0.3202**
- R²: **0.8290**

R² is the proportion of target variance explained on this specific held-out historical split. It is not percent prediction accuracy, confidence or a guarantee of performance on current housing data.

The authoritative machine-readable evidence is `exports/metrics.json`, generated by `python -m src.mlapp.pipeline`. In the validated JR05 environment, a second pipeline run reproduced the same generated metrics byte-for-byte.

## Artifact and serving controls

The selected trusted local model is stored in a versioned bundle with:

- artifact version;
- selected model name;
- canonical feature names/order;
- exact scikit-learn version;
- model object;
- preprocessing scaler when required.

Loading rejects a different scikit-learn runtime version with a safe instruction to retrain. This is a compatibility check, not a security mechanism: joblib/pickle artifacts can execute code and must never be accepted from untrusted users.

FastAPI and Streamlit use the same canonical feature order. `exports/metrics.json` distinguishes observed cleaned-training ranges from API demo/safety bounds and Streamlit convenience bounds.

## Feature importance

When Random Forest is selected, the app reports impurity-based model feature importance. It is useful for model inspection but:

- it is not causal explanation;
- it can favour some feature structures;
- it should not be interpreted as policy, fairness or intervention evidence.

## Limitations and risks

- Data reflects 1990 conditions and cannot represent current prices.
- Block-group aggregates are not individual properties.
- Geographic and socioeconomic patterns in historical data can encode structural inequities.
- Metrics on one deterministic held-out split do not establish temporal or population-wide generalisation.
- No fairness study, uncertainty interval or current-market validation is claimed.
- Estimates can be wrong even for inputs within accepted demo ranges.

## Safety controls

- constrained request schema and finite-number validation;
- extra-field rejection;
- canonical feature order;
- versioned artifact schema and exact scikit-learn compatibility check;
- safe errors for missing, corrupt, incompatible or invalid artifacts;
- non-negative finite model-output validation;
- explicit historical/non-valuation disclaimers in API, Streamlit and documentation;
- no user-controlled model uploads or artifact paths.

## Maintenance

When data, cleaning, split logic, dependencies, features, hyperparameters or artifact schema changes: rerun the real pipeline twice, verify committed metrics, rerun tests/security/Docker, update this model card and record the change in `CHANGELOG.md`.
